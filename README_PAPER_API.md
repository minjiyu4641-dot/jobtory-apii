# 논문 DB 부족 시 국회도서관 API 보충 · v4.7

DB에서 후보를 검색한 것과 답변에 쓸 논문을 확보한 것은 다릅니다. 초록·링크·발행 시점·공시와의 관련성 검사를 통과한 논문이 부족하면 API로 추가 후보를 가져와 같은 기준으로 검토합니다.

## 적용과 사용

1. 사이트 실행 터미널에서 Ctrl+C를 누릅니다.
2. ZIP 안의 파일을 기존 프로젝트의 **app.py 옆에 덮어씁니다.** `.env`, 데이터 폴더와 `data/paper_collection`은 유지합니다. v4.6의 논문·회사 DB 별도 설정도 유지됩니다.
3. 아래 명령으로 다시 실행합니다.

```powershell
python -m streamlit run jobtory_v4.py --server.port 8505
```

4. 상단 v4.7을 확인합니다.
5. 오른쪽 **논문 함께 보기**를 켜고 **논문 활용 설정 → 질문으로 자동검색 → 자동검색 대상: DB 우선 + API 보충**을 선택합니다.
6. **DB 부족 시 API로 보충**을 켠 뒤 **AI 답변 받기**를 다시 누릅니다. 원문 먼저 확인 버튼은 논문 검색을 실행하지 않습니다.

`Supabase DB`만 선택하거나 `저장된 논문 직접 선택`을 사용하면 API 보충을 실행하지 않습니다. 해당 검색 방식과 API 미사용 이유를 결과에 표시합니다.

## 이번 변경

- DB에서 검토를 통과한 논문이 3편 미만이면 API 보충 대상으로 판단합니다. 최신 연구 질문도 API 보충 대상으로 판단할 수 있습니다.
- 기존 코드는 DB에 이미 있는 ID를 모두 건너뛰고 API 앞 2페이지만 확인했습니다. 이제 초록·출처·발행연도가 비어 있던 기존 ID도 검색어당 최대 1편 재조회합니다.
- 이미 확보한 ID가 앞 페이지를 채우면 최대 6페이지까지 다음 페이지를 확인합니다. 새 ID를 먼저 조회하고, 검색어당 적합한 메타데이터 후보 최대 3편 또는 상세조회 최대 6편에서 멈춥니다.
- **질문당 국회도서관 API 최대 8회와 기존 시간당 요청 제한은 유지합니다.** 6페이지 전체를 항상 조회하는 것은 아닙니다. 검색·상세조회 모두 요청에 포함됩니다.
- 검토에 통과한 API 논문은 새 ID를 DB에 저장합니다. 같은 ID가 이미 있다면 `abstract`, `url`, `doc_url`, `doi`, `publication_year` 중 **비어 있는 항목만** API 값으로 보완합니다. 원래 값이 바뀌었으면 갱신하지 않도록 이전 값과 일치하는 조건을 함께 사용합니다.
- 초록이 이미 있는 논문을 다른 초록으로 덮어쓰거나, 무관한 논문을 억지로 연결하지 않습니다.

## 결과 읽기

| 표시 | 뜻 |
| --- | --- |
| 검색 방식 | DB만 검색했는지, DB와 API를 함께 사용했는지 표시합니다. |
| 국회도서관 API 실제 요청 N회 | 하이브리드 검색에서 실행한 검색·상세조회 요청 수입니다. 결과 재사용 시에는 이전 검색의 수라고 표시합니다. |
| API에서 연결 N편 | 그중 초록·출처·시점·관련성 검사를 통과해 답변에 연결한 논문 수입니다. 요청 수와 다릅니다. |
| API 보충 상태 | 꺼짐, 설정 확인 필요, 완료, 요청 중단, DB 근거 충분 등의 이유를 표시합니다. |
| 기존 빈 항목 보완 N편 | API에서 확인한 메타데이터를 기존 DB 레코드의 빈 항목에 저장한 수입니다. 새 논문 수와 구분합니다. |

API가 초록을 제공하지 않거나, 검색 후보가 질문과 무관하거나, 요청 한도·인증 오류가 있으면 보충 후에도 연결한 초록이 0편일 수 있습니다. 이 경우 확보한 공시로 답변하고 논문에서 확인했다고 표현하지 않습니다. API 결과 확보를 보장하거나 논문 전문을 수집하는 기능은 아닙니다.

같은 논문 ID의 빈 항목 보완에 필요한 UPDATE 권한이 없다면 보완 저장 오류를 표시하되, 이번 요청에서 검증한 API 초록은 계속 답변에 사용합니다. 논문 DB에만 쓰며 팀원 회사 DB는 변경하지 않습니다.

## 검증

실제 국회도서관 키나 유료 모델을 호출하지 않고, 모의 API·DB로 DB 0편/불완전 자료의 API 전환, 4페이지의 새 후보 검색, 기존 ID 재확인, 빈 항목의 조건부 보완, 기존 값 보존과 결과 화면의 요청 수 표시를 검증합니다. 실제 제공처의 초록 제공 여부와 사용량은 실행한 PC에서 확인해야 합니다.
